# AGENTS.md

Guidance for every agent (and human) working in this repo.

## Source of truth

`SPEC.md` defines what the project does. Read the sections your task touches before writing code. If the spec is wrong or silent on something that matters, raise it. Don't improvise behaviour the spec doesn't describe.

## Conventions

- Write only the current state. No backwards-compatibility shims, versioned comments or dead code.
- Comments say *why* the code can't show, in one line.
- Python standard library only, everywhere. `bot.py` must run on Python 3.12: no newer syntax.
- `bot.py` is the single file that gets uploaded. Only the orchestrator edits it.
- `kit/` is the organisers' starter kit, vendored unchanged. Never edit it.
- Risky logic ships with a behaviour test in `tools/test_*.py`, runnable as `python3 tools/test_x.py`.
- Done means `scripts/verify.sh` prints READY and the real thing was exercised.
- Never commit secrets, the data token, or `hands/`.
- Commits have no co-author or "generated by" lines.

## Skills

| Skill | Used for |
|---|---|
| `ponytail` (full) | All code: the smallest complete change; never cut validation or error handling. |

## Layout

- `bot.py`: the bot.
- `kit/`: engine, house bots, `local_sim.py` (real time limits, subprocesses), `fetch_hands.py`.
- `opponents/`: bots to test against.
- `tools/`: simulator, tuner, analysis, generators, tests.
- `notes/`: briefs, agent reports, the resume note.

## Commands

```
python3 kit/local_sim.py bot.py --rounds 5      # tournament conditions
python3 tools/sim.py bot.py --rounds 20          # fast, in-process
scripts/verify.sh                                # the definition of done
```
